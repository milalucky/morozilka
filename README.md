# Морозилка

Общая домашняя морозилка в мятном стиле. Вход через Google, продукты и категории в Cloud Firestore, автоматическая синхронизация между устройствами. Клиент не показывает продукты до проверки доступа. Сессия входа сохраняется в браузере; сами продукты больше не записываются в localStorage.

## Размещение

Приложение публикуется на GitHub Pages через `.github/workflows/pages.yml`. Облачная база — Firebase-проект `morozilka-home-7f3a21`, Cloud Firestore Standard в `europe-west1`. Используется бесплатный режим, платёжный аккаунт не подключён.

В базу перенесены 43 исходных продукта и 11 категорий. Разрешённые пользователи заданы в закрытом документе `settings/access`; их адреса не хранятся в публичных файлах.

## Подключение Firebase (Spark, без платёжного аккаунта)

1. Создать Firebase-проект на бесплатном плане Spark. Analytics, Cloud Functions, Storage и платный план Blaze для этого приложения не нужны.
2. Зарегистрировать веб-приложение и перенести его публичную web-конфигурацию в `firebase-config.mjs`: `export const firebaseConfig = { ... };`. Пароли, сервисные аккаунты и приватные ключи в этот файл не помещать.
3. В Authentication включить провайдер Google. В Authorized domains добавить домен размещённого сайта, например `USERNAME.github.io`, и `127.0.0.1` для локальной проверки, если она нужна.
4. Создать Cloud Firestore Standard, базу `(default)`, и опубликовать `firestore.rules`: `npx firebase deploy --project PROJECT_ID --only firestore:rules`. Открытые тестовые правила не использовать.
5. Через Firebase Console создать документ `settings/access` с полем `emails` (массив из двух точных адресов Google-аккаунтов). Клиентам запрещено менять этот документ. Адреса не требуется публиковать в GitHub.
6. Проверить вход с обеих разрешённых учётных записей и отказ для посторонней. Затем опубликовать сайт.

Установка плагина Firebase и авторизация в нём позволяют выполнить настройку из Codex. Доступ к продуктам определяется правилами базы; одного скрытого адреса или экрана входа недостаточно.

## Перенос продуктов

Исходные 43 записи перенесены в облачную базу; локальная копия сохранена в `.private/initial-inventory.json`. Этот каталог и скриншоты исключены из Git и сборки. Список не должен попадать в открытый репозиторий, даже если интерфейс защищён входом.

После первого входа в настроенную морозилку можно перенести прежний список из localStorage текущего origin или выбрать JSON-файл. При переходе с localhost на GitHub Pages старое хранилище недоступно новому адресу — используйте приватный JSON-файл. Поддерживаются отдельные поля общего веса и количества. Неуточнённый вес фарша сохраняется без исправления.

Перенос выполняется атомарно один раз и не перезаписывает уже существующие упаковки. При редактировании одного продукта с двух устройств конфликт отклоняется с просьбой открыть свежую карточку; изменения разных продуктов сохраняются независимо. Без соединения изменения недоступны; сообщение об успехе показывается после подтверждения сервера.

## Сборка и публикация

- `npm run build` — собирает только публичные файлы в `dist/`; отказывается публиковать приложение без Firebase-конфигурации.
- `npm run build -- --allow-unconfigured` — локальный просмотр экрана настройки.
- `npm start` — локальный сервер `http://127.0.0.1:4173`, раздающий только `dist/`.
- В GitHub Settings → Pages выбрать GitHub Actions. Workflow `.github/workflows/pages.yml` проверяет код, собирает `dist/` и публикует его после push в `main`. Данные продуктов при этом не меняются.

Публиковать нужно `dist/`, а не весь рабочий каталог. Скрипт сборки использует явный список файлов: `.private`, тесты, npm-пакеты и журналы Firebase в него не входят. Приложение загружает официальные браузерные модули Firebase 12.19.0 с gstatic; зависимости npm используются только для разработки и проверок.

## Проверки

Нужны Node.js и для эмулятора Java 21+:

- `npm ci`
- `npm test` — проверка весов, количества, категорий, переноса и иллюстраций.
- `npm run test:rules` — Firestore-эмулятор: два разрешённых клиента, отказ посторонним и неподтверждённой почте, валидация данных, конкурирующие изменения, live-обновления, импорт, удаление и отмена, отзыв доступа.

Проверки эмулятора используют демонстрационный проект `demo-morozilka` и не обращаются к облачной базе. Настоящий вход через Google и доступ с двух физических телефонов нужно проверить после создания проекта.
